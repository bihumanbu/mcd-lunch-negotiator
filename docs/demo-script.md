# 3 分钟演示口播稿

> 目标：让评审在 3 分钟内相信三件事——**真的调用了**、**真的能用**、**真的省钱**。
> 每个数字都是实跑结果，不要念错。

---

## 录制前准备（10 分钟，按顺序做）

**① 先冷跑一次，把数据准备好**

```bash
cd mcd-lunch-negotiator
rm -rf data                        # 清缓存，才能复现「114 次真实调用」
python src/negotiator.py 深圳 科技园
```

跑完会生成 `plan.md`，**先复制一份留底**（后面重跑会覆盖）：

```bash
cp plan.md docs/sample-plan.md
```

> ⚠️ 如果视频里想现场跑终端，**这一步之后不要再清缓存**——热启动只要 10—20 秒，画面能看；冷启动 72 秒会吃掉半条视频。

**② 录屏前跑一次预检（30 秒，别省这一步）**

```bash
python src/preflight.py
```

必须看到最后一行是 **「结论：全部通过，可以录」**。它会检查 Token、MCP 连通性、必交文件、
以及 `sample-plan.md` 里的金额是否算得平。有任何 FAIL 就别按录制键，先修。

**③ 打开四个窗口，按这个顺序摆**

| 顺序 | 窗口 | 讲什么 |
|---|---|---|
| 1 | GitHub 仓库首页（首屏那张封面图） | 开场差异化 |
| 2 | **`docs/pitch.html`（浏览器打开，一页看完）** | 核心数字，画面最抓人 |
| 3 | `docs/sample-plan.md` | 「这是脚本真实输出」，证明不是手画的 |
| 4 | WorkBuddy 自动化列表（11:25 那条）+ 终端 | 定时任务 + 真调用 |

> **为什么 2 和 3 都要**：`pitch.html` 好看但"像做过的"，`sample-plan.md` 是终端原样输出、
> 粗糙但可信。**先给好看的，再给粗糙的**——粗糙那份反而更有说服力。

**④ 录屏设置**

- 1920×1080 以上，终端字号调大到 16—18px
- 关掉微信、邮件、系统通知
- **不要剪辑**：一次说完。剪过的录屏，评委会怀疑是假的

## 0:00—0:20　开场（把差异化提前锁定）

> 「先说结论：GitHub 上这一百多个麦当劳 MCP 项目，**几乎全是在帮你一个人省钱**。
> 但办公室午饭不是一个人的事——**总有一个人，每天中午要被问一遍『吃什么』**。
> 我做的是那个人的工具：**一个人，替全办公室点单**。」

**要点**：开场 20 秒内说清「我和别人不一样」，创意分提前锁定。

## 0:20—0:50　问题（讲清为什么需要）

> 「七个人一起点麦当劳，有个坑大部分人没注意：
> **一单只能用一张券，而券绑在个人账户上。**
> 所以这不是聊天能解决的问题，是个拆单问题——
> 谁跟谁一单、每单挂哪张券、谁在减脂、谁的预算只有 25 块。
>
> 更麻烦的是，**套餐到底比单点省多少，官方从来不直接告诉你**。」

**画面**：切到 WorkBuddy 里的 Skill 界面。

## 1:10—2:00　演示二：结果（这一步必须出数字）

**先切到 `docs/pitch.html`（浏览器打开），讲三段金额和每人买法**；讲完再切到 `docs/sample-plan.md`
补一句「这是脚本原样输出，不是我做图做的」——粗糙那份反而更可信。

> 「**核心结论**：同样这些吃的——七个人、五个套餐——
> 逐个单点买要 **¥298.40**，人均 42 块 6。
> 用我的方案，**¥211.60**，人均 30 块 2。
> **省 86 块 8，29.1%。**
>
> 而且不是靠让人少吃省出来的：**7 个人全在预算内，0 个人踩到忌口**。」

切到「每人买法」：

> 「老陈没提要求，给他配 29.9 的鸡腿堡三件套；
> 小林要减脂，同样的套餐，因为它在 500 大卡分类里；
> 阿珍不吃牛肉，所以不给她配安格斯。」

切到「优惠券叠加」和「怎么下这几单」：

> 「我账户里有券。Lily 那杯燕麦奶铁 23 块，挂『中杯奶铁 7 折』券，**14 块 7**。
>
> 这里有个关键：**一单只能用一张券**。
> 所以有券的人必须单独占一单——把三个人合并成一单，等于白扔两张券。
> **最终 203 块 3，总共省 95 块 1。**
>
> 还有个约束是我实测出来的：**每单只有 15 分钟支付窗口**。
> 所以这个工具的真实定位不是我替七个人付款，而是
> **我算清楚、把链接分下去，每个人扫自己那一单**。」

## 2:00—2:40　演示三：真调用（这一步决定可信度）

切到 `docs/mcp-tools.json`，或直接在终端跑一次：

> 「这些价格不是编的。麦当劳 MCP 一共 **35 个工具**，
> 主流程用了 **5 个**：查门店、拉菜单、解剖套餐、实时计价、查券。
> 一次完整方案 **114 次真实调用**，8 线程并发，一分多钟跑完。」

展示「逐项明细」表：

> 「这一列『同内容单点』是怎么来的？
> 把套餐里每个默认商品**单独拿去官方接口计价**再加起来。
> 比如龙焰芝士棒鸡腿堡三件套，套餐 29.9，
> 单点一个汉堡 27、一份中薯 13.5、一杯雪碧 10——**50.5**。
>
> **这里有个必须交代的细节**：套餐里的『可乐中杯』单点返回 0，因为它不单卖。
> 我没有把它当免费算，而是按同档位的雪碧 10 块做**保守估值**，并且在文档里标出来。
> 所以这些差额是**下限**，不是虚高。」

**这一步是加分点**：主动交代数据陷阱，比任何功能都更能证明「这是真的做过」。

### 录屏前必读（两条）

1. **画面用 `docs/sample-plan.md`，不要中途重跑。** 带缓存重跑会把「114 次」覆盖成十几次，嘴上一说数字，画面对不上，评委当场能抓。
2. **调用次数的完整说法**：冷启动共发起 151 次数据查询，其中真实 MCP 调用 **114 次**、命中本地缓存 37 次。只说「114 次真实调用」是对的，但如果评委问「怎么算的」，就补这句。

## 常见追问准备

**Q：券为什么不多用几张？**
A：一单只能用一张券，这是官方限制。所以我按「一单一人」分配，把券用在单价最高的匹配商品上。

**Q：为什么不做自动下单？**
A：下单接口我实测过——能返回 `payH5Url`，订单 15 分钟内有效。但它不自动付款：写操作失控是这类工具最大的风险，而且「算清楚 + 给链接」已经把活干完了，最后一步不该让 AI 代劳。

**Q：和榜上那些省钱工具有什么不同？**
A：它们是单人视角，我做的是团队视角。单人省钱解决「我想吃好」，团队拆单解决「七个人怎么点」——后者是结构性问题，不是加个参数能覆盖的。

**Q：多账户 Token 能不能管？**
A：不能，也不该做。券绑个人账户，跨账户管理在规则上就不成立。定位就是「一个人的账号替全组点单」。
